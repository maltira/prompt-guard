# Данные

Выборки для обучения и оценки детекторов prompt injection.

## Выборки

| Файл | Размер | Для чего |
|---|---|---|
| `splits/train.jsonl` | 6 055 | обучение детекторов |
| `splits/val.jsonl` | 1 010 | подбор порогов и гиперпараметров, ранняя остановка |
| `splits/golden.jsonl` | 450 | итоговая оценка, только для измерений |
| `splits/stats.json` | | статистика по классам, языкам, категориям и источникам |
| `splits/golden.sha256` | | SHA-256 файла `golden.jsonl`, единственное место, где хранится хэш |

**Golden не используется ни для обучения, ни для подбора настроек.** Файл `splits/golden.jsonl` зафиксирован и больше не меняется.

**Хэш golden** хранится в одном месте - [splits/golden.sha256](splits/golden.sha256). Он нужен, чтобы заметить, что golden изменился: если хэш другой, прежние оценки сравнивать с новыми нельзя.

- Читают его все: `eval/run_eval.py` перед оценкой на golden сверяет файл с хэшем и останавливается при расхождении. Вручную: `sha256sum data/splits/golden.jsonl` и сравнить с содержимым `golden.sha256`.
- Пишет его только [build_splits.py](build_splits.py), и по правилам: нет файла - создаёт; хэш тот же - ничего не делает; хэш другой - **останавливается, ничего не перезаписывая**. Обновить хэш можно только явным флагом `python -m data.build_splits --update-golden-hash`, когда вы сознательно меняете golden.
- Логика хранения и проверки - в [golden_hash.py](golden_hash.py).

### Golden (450)

- 225 атак и 225 безопасных; 200 английских и 250 русских.
- Безопасные включают 92 пограничных (`benign_borderline`): тексты с лексикой атаки или признаками мошенничества, но безопасные.
- Все тексты написаны вручную. Русские: 175 адаптированы с английских сценариев (`custom:ru_adapted`), 75 придуманы с нуля (`custom:ru_native`). Метрики для этих срезов стоит считать отдельно.
- Все тексты считаются недоверенным содержимым (письмо, документ, страница), которое обрабатывает ассистент. Инструкция внутри такого текста - внедрение. Запрос самого пользователя в golden не входит.
- Категория атаки - основной приём, а не единственный: категории не исключают друг друга (например, смена роли может служить для выманивания секрета). Метрики по категориям читать с оговоркой.

### Train и val

Собираются из открытых наборов и шаблонной синтетики, делятся 85/15 с сохранением пропорций по классу, языку и источнику.

## Формат записи

Одна запись на строку JSONL, поля описаны в [schema.py](schema.py):

| Поле | Значения |
|---|---|
| `id` | уникальный идентификатор |
| `text` | текст письма, документа или запроса |
| `label` | `attack` или `benign` |
| `lang` | `ru` или `en` |
| `category` | атаки: `instruction_override`, `secret_exfiltration`, `fake_system_message`, `role_hijack`, `hidden_instruction`, `output_manipulation`, `direct_injection` и категории neuralchemy; безопасные: `benign`, `benign_borderline` |
| `source` | происхождение, см. ниже |

Значения `source`: `hf:<набор>` (открытый набор), `synthetic:template` и `synthetic:template_short` (шаблоны), `custom:handwritten` (английский golden), `custom:ru_adapted`, `custom:ru_native`.

## Устройство папки

```
data/
  schema.py        формат записи, чтение и запись JSONL
  synth.py         генератор шаблонных примеров для train и val
  build_golden.py  собирает golden из ручных файлов
  build_splits.py  собирает train, val, golden и stats.json
  custom/          ручные тексты golden: gold_{en,ru}_{attack,benign}.py
  raw/             скачанные открытые наборы (в git не попадают)
  splits/          результат сборки
```

В `custom/gold_*.py` тексты лежат списками пар `(категория, текст)`. В русских файлах два списка: `ITEMS` (адаптированные) и `NATIVE` (придуманные с нуля).

## Как собираются train и val

`python -m data.build_splits` делает по шагам:

1. Загружает открытые наборы из `raw/` (таблица ниже). Из атак оставляет только фразы, похожие на инструкцию ассистенту (слова вроде «ignore», «reveal», «system prompt», «игнорируй», «пароль», «инструкции»), длиной от 15 до 350 символов, не меньше 4 слов, без кода, мусорных и шифрованных строк (для русских фраз не меньше 90% кириллицы), и отбрасывает категории вне модели угроз (джейлбрейки, смена личности, шифрование, многоходовые атаки). Для русских фраз добавлены правила: без привязки к играм-источникам (Mosscap, Gandalf, hackaprompt, кодировки), не короче 40 символов, вопросы без команды отбрасываются, и не больше 35% фраз про пароль и секрет, иначе детектор выучит «пароль = атака». Недостающие типы русских атак (подмена задачи, фальшивое системное сообщение, вытягивание инструкций) получены переводом английских фраз локальной моделью `Helsinki-NLP/opus-mt-en-ru` (`python -m data.translate_payloads`, без обращений к API); перевод и его оригинал при делении выборок попадают в одну группу.
2. **Вставляет фразы атак в нейтральные письма** (`synth.py`, носители в `mail_templates.py`). Носитель случайный: письмо с заголовками, цитатой, пересылкой, подписью и дисклеймером (около 58%), автоматическое уведомление, тикет, переписка, рассылка, заметки. Фраза вставляется нейтральным способом: просто в текст, P.S., HTML-комментарий, скрытый блок, футер или цитата. Половина фраз попадает в два разных носителя. Небольшая доля (15%) остаётся короткими прямыми текстами.
3. Безопасные запросы из открытых наборов **в письма не вставляются**: по модели угроз просьба, адресованная ассистенту внутри письма, и есть внедрение, пусть даже безобидная. Они остаются короткими отдельными текстами (примерно 270 штук). Безопасные письма делаются из шаблонов, причём около 55% из них получают ту же разметку (комментарии, скрытые блоки, цитаты), что и письма с атаками, чтобы разметка и длина не выдавали атаку.
4. **Добавляет шаблонные примеры:** письма с атакой в почтовой формулировке («при пересказе этого письма…», «в черновике ответа…»), обычные и пограничные безопасные письма, и **трудные безопасные тексты**: те же фразы атак из открытых наборов, но процитированные в предупреждениях, обучающих материалах и разборах инцидентов. Одна и та же фраза встречается и как атака, и как цитата в безобидном контексте, поэтому детектор должен смотреть на контекст.
5. Определяет язык, отбрасывает тексты не на русском и английском, убирает точные и почти-дубликаты (косинус tf-idf по символьным n-граммам от 0,92).
6. **Убирает всё, что похоже на golden:** косинус от 0,60 и больше 2 общих словесных отрезков по 6 слов. Так в обучение не попадают копии моих формулировок.
7. Делит на train и val (примерно 86/14) **группами по фразе атаки**: одна фраза и все её копии в разных письмах и цитаты в безобидных текстах целиком попадают либо в train, либо в val. Проверяет, что id не пересекаются между train, val и golden, пишет `splits/*.jsonl` и `stats.json`.

Сборка детерминирована (`SEED = 13`). Golden каждый раз заново собирается из `custom/gold_*.py`. Если после правки этих файлов хэш изменился, сборка остановится, пока вы не передадите `--update-golden-hash`.

Состав train: 3 062 атаки и 2 993 безопасных текста (английский 3 431, русский 2 624). Разметка (комментарии, скрытые блоки, подписи, цитаты) есть у 61% атак и у 57% безопасных, медиана длины 417 и 383 символа, коротких текстов (меньше 150 символов) 6% и 9%: различие небольшое, но остаётся.

### Открытые наборы

| Набор | Лицензия | Что берём |
|---|---|---|
| [deepset/prompt-injections](https://huggingface.co/datasets/deepset/prompt-injections) | Apache-2.0 | английские примеры; атаки только инструкции ассистенту |
| [S-Labs/prompt-injection-dataset](https://huggingface.co/datasets/S-Labs/prompt-injection-dataset) | MIT | до 800 фраз атак; до 60 безопасных запросов |
| [neuralchemy/Prompt-injection-dataset](https://huggingface.co/datasets/neuralchemy/Prompt-injection-dataset) | Apache-2.0 | `core`, без категорий вне модели угроз; трудные безопасные примеры |
| [dmtrdr/russian_prompt_injections](https://huggingface.co/datasets/dmtrdr/russian_prompt_injections) | Apache-2.0 | около 490 русских фраз атак после фильтров, из источников Lakera mosscap и hackaprompt (джейлбрейк-набор исключён); плюс около 280 переведённых с английского |
| [IlyaGusev/ru_turbo_alpaca](https://huggingface.co/datasets/IlyaGusev/ru_turbo_alpaca) | CC-BY-4.0 | 100 русских безопасных запросов |

Русские атаки из `dmtrdr` - машинный перевод английских наборов, а сам набор собран из источников с разными лицензиями. В golden они не используются.

Шаблонная синтетика: английский: 200 писем с атакой, 700 безопасных, 250 пограничных безопасных, 20 коротких запросов; русский: 380 писем с атакой, 430 безопасных, 250 пограничных безопасных, 20 коротких запросов; на каждый язык ещё 500 безопасных писем с разметкой и до 350 трудных безопасных (цитаты фраз атак в предупреждениях).

### Как восстановить `raw/`

Файлы скачиваются вручную с Hugging Face, имя локального файла - путь в репозитории, где `/` заменён на `__`:

- `raw/deepset__prompt-injections/*.parquet` (из `data/`)
- `raw/S-Labs__prompt-injection-dataset/data__train.csv`
- `raw/neuralchemy__Prompt-injection-dataset/core__{train,validation,test}-00000-of-00001.parquet`
- `raw/dmtrdr__russian_prompt_injections/dataset.json`
- `raw/IlyaGusev__ru_turbo_alpaca/ru_turbo_alpaca.jsonl` (распаковать `ru_turbo_alpaca.jsonl.zst` командой `zstd -d`)
- `raw/translated/en_ru_payloads.jsonl` создаётся командой `uv run python -m data.translate_payloads --n 700` (нужны английские наборы выше; модель перевода скачивается при первом запуске)

## Известные ограничения

- Golden небольшой: погрешность метрик по срезам заметная (по паре «класс × язык» около ±6-7 п.п.), по русским «с нуля» (25 атак и 50 безопасных) выше.
- Русские адаптированные примеры повторяют сценарии английских, поэтому метрики по русскому - не полностью независимый эксперимент.
- Атаки и их безопасные «чистые версии» в golden написаны одним автором и очень похожи по носителю; это сложный тест, но он может отличаться от реального распределения.
- Синтетика в train однообразнее настоящих писем: годится для обучения, но не для оценки.
- На val простые детекторы показывают качество заметно выше, чем на golden. Итоговые цифры брать только с golden.
- Открытые наборы определяют атаку шире модели угроз проекта (см. [../README.md](../README.md)): ролевые просьбы и джейлбрейки от пользователя там помечены как атаки. Мы отфильтровали такие категории и оставили только фразы, похожие на инструкцию ассистенту, но простой фильтр по словам не идеален: в train и val остаётся некоторое количество примеров, спорных по нашему определению. Метки val поэтому надёжнее, чем в исходных наборах, но всё равно уступают golden.
- Вставка фраз в письма делает атаки реалистичнее, но сами письма (носители) собираются из шаблонов, которые написал я: они однообразнее настоящей почты. Фразы атак из русского набора (`dmtrdr`) - машинный перевод и местами звучат неестественно или бессмысленно.
