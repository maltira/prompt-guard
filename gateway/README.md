# Шлюз

Проверяет письмо выбранным детектором до того, как оно попадёт к ИИ-ассистенту.

Запуск: `uv run uvicorn gateway.app:app --port 8000` или вместе с мишенью `docker compose up` (порты 8000 и 8001 на `127.0.0.1`, веса моделей берутся из кэша huggingface на хосте, результаты из `./results`)

| Эндпоинт | Что делает |
|---|---|
| `POST /check` | тело `{"subject": "...", "body": "...", "detector": "..."}`; тело письма может быть текстом или HTML; ответ: `label`, `score`, `action` (`allow` или `block`), `stage`, `latency_ms`, `hidden_found`, `hidden_text` |
| `POST /compare` | то же письмо (`subject`, `body`) прогоняется по очереди через все готовые детекторы; ответ: `results` (у каждого `label`, `score`, `action`, `stage`, `latency_ms`, при сбое `error`), `unavailable` с причинами, `summary` (сколько назвали атакой), `hidden_found`, `hidden_text` |
| `GET /detectors` | готовые детекторы и причины, по которым остальные недоступны |
| `GET /metrics` | счётчики по журналу решений |
| `GET /health` | статус и детектор по умолчанию |

Без `detector` берётся лучший из готовых (порядок в `gateway/registry.py`). Детектор готов, если есть его файлы и веса модели в кэше huggingface: например, LoRA недоступна, пока нет базы xlm-roberta, а судье нужны переменные из `.env`.

Журнал решений: `results/gateway/decisions.jsonl` (путь меняется переменной `GATEWAY_LOG`, в git не попадает).

Что проверяется: тема и тело вместе, в том виде, в каком их видели детекторы при обучении и оценке (сырой текст с разметкой). Разбор HTML (`gateway/parse.py`) нужен для пояснения: он находит текст, скрытый от человека (`display:none`, белый или микроскопический шрифт, комментарии) и возвращает его в `hidden_text`. Вложения и заголовки кроме темы не разбираются.

Сравнение (`/compare`): решение «блокировать» там не принимается, это только наглядное сравнение. Судья идёт раньше каскадов, и они берут его ответ из общего кэша, поэтому на письмо приходится не больше одного запроса к API. Сбой одного детектора возвращается как `error` и остальные не ломает. Запуски сравнения пишутся в журнал с пометкой `mode: compare` и в `/metrics` не входят.

Время в сравнении не независимо: модели эмбеддингов загружаются один раз на все свои классификаторы, а вектор письма хранится в памяти. Кодирование оплачивает первый классификатор модели, а следующие видят вектор из памяти, и повторное письмо идёт из памяти целиком. Для оценки задержки детектора пользуйтесь `/check` или результатами `eval/run_eval`.
