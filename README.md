# Детекция prompt injection

**Детекция prompt injection: сравнение подходов, каскадная архитектура и устойчивость к адаптивным атакам**

Проект для конференции «Прикладное и системное программирование» (09.11).

## Проблема

Языковые модели не умеют надёжно отличать данные для обработки от команд для исполнения. Злоумышленник может спрятать инструкцию в письме или документе, и ИИ-ассистент выполнит её. Проект строит защитный шлюз, который проверяет текст до того, как он попадёт в модель.

## Цель и вопросы

Построить шлюз защиты для ИИ-приложений и экспериментально оценить способы детекции prompt injection.

1. Какой способ детекции лучше по точности, скорости и стоимости?
2. Даёт ли каскад «быстрый фильтр → точный судья» качество судьи по цене фильтра?
3. Насколько детектор устойчив к атакам, подстроенным под него, и помогает ли дообучение?

## Архитектура

```
Текст (письмо, документ, запрос)
        ▼
   Шлюз защиты (HTTP API)
        ├─ Ступень 1: быстрый фильтр (эмбеддинги + классификатор)
        ├─ Ступень 2: точный судья (для сомнительных случаев)
        └─ Журнал решений и метрики
        ▼
  Ассистент-мишень (пересказ писем) ──► LLM
```

- **Шлюз.** HTTP API (`/check`, `/metrics`). Опционально: обёртка в виде MCP-инструмента.
- **Ассистент-мишень.** Делает краткое содержание писем. В его системной подсказке лежит фиктивный секрет, по утечке которого видно успех атаки. Режимы: напрямую и через шлюз.
- **Журнал.** Для каждого решения: ступень, задержка, стоимость.

## Сравниваемые подходы

| # | Подход | Суть |
|---|---|---|
| 1 | Эмбеддинги + классификатор | Вектор смысла текста и лёгкий классификатор (логрегрессия, kNN, малая нейросеть) |
| 2 | LoRA | Дообучение компактной модели малыми надстройками |
| 3 | Prompt tuning | Обучаемые «мягкие» векторы перед входом замороженной модели |
| 4 | LLM как судья | Zero-/few-shot запрос к большой модели |
| 5 | Каскад | Ступень 1 отсекает очевидное, сомнительное идёт судье |

Дополнительно (по времени): эмбеддинги энкодера против декодера, маленький трансформер с нуля как контрольная точка.

## Данные

**Golden set**: 300–500 вручную проверенных примеров (поровну атак и безопасных, русский и английский, включая пограничные безобидные). Не участвует в обучении и одинаков для всех способов. Выборки разделяются в самом начале: обучающая, валидационная, golden set.

Источники: публичные наборы по prompt injection (Hugging Face) и собственные примеры.

Состав выборок, формат записи, хэш golden и порядок сборки описаны в [data/README.md](data/README.md).

## Эксперименты

| Эксперимент | Метрики |
|---|---|
| Сравнение подходов на golden set | recall, precision, доля ложных срабатываний |
| Скорость и стоимость | задержка, цена на 1000 запросов |
| Каскад против одиночных способов | точность, задержка, доля запросов на ступень 2 |
| Адаптивные атаки | падение recall, восстановление после дообучения |

## Демонстрация

1. Ассистент без защиты обрабатывает безобидное письмо.
2. Письмо с внедрённой инструкцией: ассистент выдаёт фиктивный секрет.
3. Через шлюз: безобидное проходит, вредное блокируется, на панели видна сработавшая ступень.
4. Адаптивная атака: часть обходов проходит, защита усиливается.
5. Итоговая таблица сравнения.

Все тестовые данные безобидны: секрет фиктивный, атаки направлены только на собственного ассистента.
