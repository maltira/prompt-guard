# Детекция prompt injection

**Исследование методов обнаружения prompt injection для ИИ-ассистентов: сравнение подходов**

## О проекте

Ассистенты, которые разбирают почту (пересказ писем, сортировка, черновики ответов), читают тексты, написанные посторонними людьми. Языковая модель не отличает данные от команд, поэтому инструкция, спрятанная в письме или во вложенном документе, может быть выполнена ассистентом. Проект строит сканер входящей почты: защитный шлюз проверяет текст письма и документа до того, как он попадёт в модель, и экспериментально сравнивает способы детекции.

## Модель угроз

- **Что защищаем:** ИИ-ассистент, который обрабатывает входящие письма и документы из них (пересказ, классификация, извлечение данных, черновики ответов). Языки: русский и английский.
- **Атакующий:** внешний отправитель. Он пишет письмо или документ, но не видит системных настроек ассистента и не меняет запросов пользователя.
- **Что считается атакой:** инструкция в тексте письма или документа, адресованная ассистенту, чтобы подменить задачу, вытянуть скрытые инструкции или секреты, сменить роль ассистента или выдать себя за системное сообщение, спрятать команду (HTML, невидимый текст) либо исказить результат (факты, суммы, оценки).
- **Что атакой не считается и должно проходить:** письма с командами для людей («игнорируйте моё прошлое письмо», «используйте новую форму»), уведомления ИТ и службы безопасности, обучающие тексты и статьи о prompt injection, сценарии и ролевые игры, обычные просьбы пользователя.
- **Вне рамок:** прямые запросы пользователя к ассистенту (джейлбрейки и ролевые просьбы от самого пользователя), вредный по содержанию текст, изображения, аудио и бинарные вложения, многоходовые диалоги, атаки на инструменты с реальными действиями, фишинг, адресованный человеку, а не ассистенту.
- **Следствие для данных:** golden и судья соответствуют этой модели. Открытые наборы в обучении определяют атаку шире (прямые запросы и джейлбрейки), поэтому их метки не всегда совпадают с моделью угроз; основные выводы делаются по golden, подробности в [data/README.md](data/README.md).

## Вопросы исследования

1. Какой способ детекции лучше по точности, скорости и стоимости?
2. Даёт ли каскад «быстрый фильтр → точный судья» качество судьи по цене фильтра?
3. Насколько детектор устойчив к атакам, подстроенным под него, и помогает ли дообучение? (не оценивалось, см. этап 7 в [PLAN.md](docs/PLAN.md))

Сравниваемые подходы: эмбеддинги + классификатор, LoRA, prompt tuning, LLM как судья (Haiku 5.5), каскад. Оценка идёт на отдельном вручную написанном наборе golden (русский и английский). Все тестовые данные безобидны.

## Как запустить

Нужны Python 3.12 и [uv](https://docs.astral.sh/uv/).

```
uv sync                      # зависимости (torch ставится в CPU-версии)
cp .env.example .env         # доступ к LLM нужен только судье
uv run pytest                # тесты

# данные: нужны скачанные наборы в data/raw/ (список и порядок в data/README.md)
uv run python -m data.build_splits

# обучить детектор на эмбеддингах и оценить
uv run python -m detectors.implementations.embeddings --model intfloat/multilingual-e5-base --kind mlp
uv run python -m eval.run_eval --detector embeddings-e5-base-mlp --split val
```

- Детекторы для `--detector`: `keyword`, `embeddings-e5-{small,base,large}` и с суффиксом `-knn` или `-mlp`.
- Для разработки используйте `--split val`; `golden` только для итоговых цифр.
- Эмбеддинги всех трёх моделей e5 считаются в Colab на GPU ([notebooks/embed_e5.ipynb](notebooks/embed_e5.ipynb)), результат кладётся в `results/cache/embeddings/`. Классификаторы обучаются локально с флагом `--cache-only`.

## Структура

```
data/         выборки, сборка, ручной golden (data/README.md)
detectors/    интерфейс Detector и реализации (implementations/)
eval/         запуск оценки и метрики (eval/README.md)
notebooks/    ноутбуки для Colab
results/      метрики и подбор настроек по детекторам, кэш (не в git)
tests/        тесты
```

Сервисы лежат в `services/` (бэкенд-шлюз и фронтенд), входная точка nginx в `nginx/`; шлюз описан в [services/backend/gateway/README.md](services/backend/gateway/README.md).
